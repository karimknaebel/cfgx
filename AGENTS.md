## Docs
Docs live in `docs/` and are built via Zensical.

## Versioning
We use SemVer. In particular, while this library is in 0.x.x we will do breaking changes without migration path or deprecation behavior on minor releases.

## Commit messages
Use [Scoped Commits](https://scopedcommits.com/): `<scope>: <description>`.
The scope names the affected area, such as `config`, `cli`, `docs`, or `agents`.
Keep the description short and imperative, for example:
`config: compose files and inline dictionaries`.
Use the body to explain motivation and tradeoffs when needed.
Do not use Conventional Commit type prefixes such as `feat`, `fix`, or `chore`.
